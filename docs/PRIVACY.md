# Provenance 隐私与数据安全政策

> 私人数据保护优先于功能、便利与性能。

## 1. 默认原则

- **不上传**：Python 包不包含网络客户端、遥测或云端同步逻辑。
- **不自动公开**：运行数据与派生产物默认均视为私人内容。
- **最小读取**：每个工作流只读取完成当前任务所需的本地来源。
- **先预览后写入**：同步入口默认只预览；`--run` 是独立写入授权。
- **高价值内容人工确认**：状态、结论、阻塞项和下一步先进入草稿。
- **失败保守**：路径、项目身份、锁或数据格式无法可信验证时停止，不猜测。

`01-capture/` 是独立、可选的浏览器端生产器。它只在用户点击导出后访问当前
Provider 的同源接口，并只生成用户请求的本地 ZIP；Python 包不会自动发现、
启动或控制它。扩展的精确数据范围与权限见
[`01-capture/PRIVACY.md`](../01-capture/PRIVACY.md)。

## 2. 数据分类

### 原始敏感层

包括浏览器或其他工具导出的 ZIP、本地 Agent 日志、PDF/Office/图片附件与其他
原始来源。
这些数据可能包含未公开研究、身份、位置、凭据或第三方信息。它们必须保持
本地，不进入 Git，也不能作为 Issue、测试夹具或演示材料上传。

### 脱敏工作层

摄取器在对象值层执行常见密钥、令牌、邮箱、IP、URL 凭据与 home 用户名
擦洗，并可按本地 `aliases.json` 做稳定假名化。该层位于 `inbox/`。

脱敏并非匿名化证明。未公开研究结论、独特措辞、时间线与关系仍可能重新识别
用户，因此 `inbox/` 仍默认属于私人数据。

### 受保护状态

`sync-state/`、队列、inflight、pending、draft、journal、Approvals 派生状态和
`aliases.json` 均可能包含身份映射或项目决策。它们不得被公开、同步到不受信任
位置或用于公共搜索索引。

### 派生产物

`profile/`、`memory/`、`vault/`、`output/`、`_prep/` 与 `search-index.db` 是从
私人输入生成的内容，也默认保持私有。去标识化画像仍需人工审阅后才能对外使用。

## 3. 附件

附件按原始字节复制，不承诺擦除 EXIF、文档作者、批注、隐藏工作表、嵌入对象或
其他元数据。任何附件在单独完成内容与元数据审查前都不得公开。

## 4. Agent 与模型边界

Provenance 的两个 Skill 要求只使用脱敏、allowlist 的输入，并禁止联网、遥测、
外部记忆写入与跨会话读取。Python 包不会调用模型。

宿主 Agent 仍受其自身的模型提供方、联网能力和保留策略约束。运行 Skill 前，
用户必须确认宿主配置符合本地隐私要求；若不能确认，不应向该 Agent 提供私人数据。

## 5. 项目解析与摘要

会话只有映射到已登记、非空的 `project_id` 后，才允许生成 scaffold。未解析事件
保留在受保护 inflight 状态，且不得生成 `session-summary/1.0`、timeline 或草稿。

填充 Agent 只能通过 `prov-sync-pending` 读取一个脱敏 scaffold，并通过
`prov-sync-fill` 提交不含路径、项目身份或时间戳的 fill。身份由本地程序绑定。

## 6. 版本库边界

公开仓库只允许：

- 源码与不含用户配置的模板；
- 产品与技术文档；
- `01-capture/` 中经审查的源码、文档与合成测试；
- 明确标记的合成项目、示例身份与保留示例域名；
- 不包含真实凭据的回归测试。

以下内容必须忽略并由公开树门禁拒绝：运行数据目录、数据库、JSONL 会话、
真实别名表、`.env`/token/key 文件、Agent 本机状态、审计草稿、本机治理文件与
生成的扩展 ZIP。

## 7. 测试与问题报告

- 测试只在隔离临时目录运行，不读取或删除用户数据。
- 公开复现必须使用 `C:\ScriptoriumDemo\...`、`example.com` 与 XQ-17 合成项目。
- 不在日志、截图、CI artifact 或 Issue 中暴露真实路径、会话 ID、邮箱或数据统计。
- 怀疑存在泄露时，先停止发布并检查 Git 对象与远端可见性，再构造合成回归测试。

## 8. 删除与恢复

原始数据、备份、配置和授权状态的删除必须由用户明确指定目标。程序与维护者不得
把“清理派生缓存”的授权扩展为删除私人数据。可重建产物与不可恢复来源必须明确
区分。
